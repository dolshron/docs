NadaPay gives developers and businesses a single API platform to move money across global markets. Whether you are embedding a checkout widget in a web app, sending bulk payouts to beneficiaries, issuing virtual cards, or running a multi-tenant platform for sub-merchants, NadaPay provides the primitives you need without stitching together multiple payment providers.

## Product Pillars

NadaPay is organized into five capability areas. Each area has its own set of APIs and guides.

## Who NadaPay Is For

NadaPay is designed for:

- **Developers** who need a well-structured REST API, clear error messages, and sandbox environments for safe integration testing.
- **Businesses** that operate across multiple markets and need a single platform for inbound payments, outbound payouts, and financial account management.
- **Platforms and marketplaces** that onboard sub-merchants and need to route settlements, apply fee markups, and manage organizations at scale.

## API Base URL

All API requests go to the following base URL:

```
https://core.nadapay.io/api/v1
```

Use this URL as the prefix for every endpoint documented in these guides. For example, to list your financial accounts you call `GET https://core.nadapay.io/api/v1/organizations/accounts`.

## Sandbox and Production Environments

NadaPay operates two fully isolated environments so you can build and test without touching real money.

| Environment | API Key Prefix | Public Key Prefix | Purpose |
|---|---|---|---|
| Sandbox | `np_test_...` | `npk_test_...` | Integration testing with simulated transactions |
| Production | `np_live_...` | `npk_live_...` | Real money and live customers |

<Note>
  Sandbox keys only work against the sandbox environment and production keys only work in production. There is no cross-environment access.
</Note>

Switch between environments by swapping your API key. No code changes are required beyond the key itself.
