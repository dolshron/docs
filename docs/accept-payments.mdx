NadaPay Checkout gives you a fully hosted payment widget you embed directly in your application. When the customer clicks Pay, your backend creates a checkout session and your frontend opens the widget — the customer never leaves your page. This guide walks you through the complete integration from loading the SDK to verifying the completed payment.

**Time to complete:** 15 minutes

## Prerequisites

- A NadaPay account with a sandbox API secret key (`np_test_...`) and public key (`npk_test_...`).
- A backend that can make authenticated requests to the NadaPay API.
- A frontend page where you will embed the Pay button.

<Note>
  Your frontend never calls the NadaPay API directly with a secret key. The session is always created on your backend. Public keys (`npk_test_` / `npk_live_`) are the only credentials that belong in browser code.
</Note>

## How It Works

Your frontend never creates a checkout session directly. When the customer clicks Pay, your frontend asks your backend to create a session, then opens Checkout with the returned `np_reference_id`.

```
Customer clicks Pay
  ↓
Frontend calls your backend
  ↓
Backend calls POST /checkout/sessions
  ↓
Frontend opens NadaPay Checkout
  ↓
Customer pays
  ↓
Backend verifies the session
  ↓
Order is fulfilled
```

<Steps>

  <Step title="Load and Initialize Checkout">
    Load the Checkout SDK and call `NadaPay.init()` once when the page loads. Pass your **public key** — not your secret key — to the `key` option.

    ```html
    <script src="https://js.nadapay.io/v1/inline.js" async></script>
    <script>
      window.addEventListener('load', function () {
        NadaPay.init({
          key: 'npk_test_xxxxxxxxxxxx',
          environment: 'sandbox',
          checkoutType: 'CUSTOM',
          currency: 'USD',

          onSuccess: function (result) {
            fetch('/api/orders/verify', {
              method: 'POST',
              headers: { 'Content-Type': 'application/json' },
              body: JSON.stringify({ reference: result.reference })
            });
          },

          onFailure: function (result) {
            console.log('Payment failed:', result.reason, result.message);
          },

          onClose: function () {
            console.log('Checkout closed');
          }
        });
      });
    </script>
    ```

    Use `npk_test_` public keys in sandbox and `npk_live_` public keys in production. Public keys are safe in browser code; secret keys are not.

    <Tip>
      Call `NadaPay.init()` exactly once per page load. Calling it multiple times or after the page has loaded can cause the widget to misbehave.
    </Tip>
  </Step>

  <Step title="Create the Session on Pay Click">
    Call your backend from the button click handler. Wait for the backend to return `np_reference_id`, then call `NadaPay.open()`.

    ```html
    <button id="pay-button">Pay $245.00</button>
    <p id="status"></p>

    <script>
      document.getElementById('pay-button').addEventListener('click', async function () {
        const response = await fetch('/api/checkout/session', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ orderId: 'ORD-4821' })
        });

        if (!response.ok) {
          document.getElementById('status').textContent = 'Could not start checkout.';
          return;
        }

        const session = await response.json();

        NadaPay.open({
          amount: session.amount,
          ref: session.np_reference_id,
          metadata: {
            order_id: 'ORD-4821'
          }
        });
      });
    </script>
    ```

    Save `np_reference_id`. You will verify it after the customer completes payment.
  </Step>

  <Step title="Create the NadaPay Checkout Session on Your Backend">
    Your backend calls NadaPay with your secret key. The authoritative amount comes from this backend session — never trust the amount sent from the frontend.

    ```javascript
    app.post('/api/checkout/session', async function (req, res) {
      const { orderId } = req.body;
      const order = await getOrder(orderId);

      const response = await fetch('https://core.nadapay.io/api/v1/checkout/sessions', {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'x-api-key': process.env.NADAPAY_SECRET_KEY
        },
        body: JSON.stringify({
          merchant_id: 'your_merchant_id',
          amount_cents: order.amountCents,
          currency: 'USD',
          metadata: {
            order_id: order.id,
            customer_email: order.customerEmail
          }
        })
      });

      if (!response.ok) {
        return res.status(502).json({ message: 'Unable to create checkout session' });
      }

      const session = await response.json();

      res.json({
        np_reference_id: session.np_reference_id,
        amount: order.amount
      });
    });
    ```

    The NadaPay API responds with:

    ```json
    {
      "np_reference_id": "NP-P-CHECKOUT-4821-K9XZ",
      "amount": 245.00
    }
    ```

    Pass `np_reference_id` to `NadaPay.open()` as `ref`.
  </Step>

  <Step title="Verify the Payment Before Fulfilment">
    When `onSuccess` fires in the browser, verify the reference on your backend before shipping goods, unlocking content, or provisioning access. A successful callback from the frontend is not sufficient proof of payment on its own.

    ```javascript
    app.post('/api/orders/verify', async function (req, res) {
      const { reference } = req.body;

      const response = await fetch(
        `https://core.nadapay.io/api/v1/checkout/sessions/${reference}`,
        {
          headers: {
            'x-api-key': process.env.NADAPAY_SECRET_KEY
          }
        }
      );

      if (!response.ok) {
        return res.status(502).json({ message: 'Unable to verify payment' });
      }

      const session = await response.json();

      if (session.status !== 'PAID') {
        return res.status(400).json({ message: 'Payment is not complete' });
      }

      await fulfillOrder(session.metadata.order_id);

      res.json({ status: 'fulfilled' });
    });
    ```

    Fulfil the order only after your backend confirms the session `status` is `PAID`.
  </Step>

</Steps>

## What Success Looks Like

- Checkout opens only after your backend creates a session.
- Your frontend passes `np_reference_id` to `NadaPay.open()` as `ref`.
- Your backend verifies the reference before fulfilling any order.
- Your production frontend uses an `npk_live_` public key.
- Your secret key never appears in browser code.

## Troubleshooting

<Accordion title="Checkout does not open">
  Confirm `NadaPay.init()` ran before `NadaPay.open()` and that `NadaPay.open()` is called from a direct user interaction such as a button click. Browsers may block programmatic opens that are not triggered by a user gesture.
</Accordion>

<Accordion title="The amount looks wrong">
  Use your currency consistently. Send `$245.00` to the session API as `24500` cents and pass `245.00` to the frontend display amount. The session's `amount_cents` field is the authoritative value.
</Accordion>

<Accordion title="Payment succeeds in the browser but the order is not fulfilled">
  Check your backend verification endpoint. The order should only be fulfilled after `GET /checkout/sessions/{reference}` confirms the session status is `PAID`. Log the full response body from the verification call to identify any status mismatch.
</Accordion>

<Accordion title="I get a 401 error creating the session">
  Ensure your backend is passing the `x-api-key` header with your secret key (`np_test_` for sandbox, `np_live_` for production). Do not use a public key (`npk_`) for backend session creation.
</Accordion>
