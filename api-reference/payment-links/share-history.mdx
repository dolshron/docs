---
title: 'GET /organization/payment-links/shares/history — View Share History'
sidebarTitle: 'Share History'
description: 'Retrieve a paginated history of all payment link share events, including recipient emails, timestamps, and linked payment link IDs.'
---

This endpoint returns a paginated list of every share event recorded under your organization — every time you sent a payment link to a recipient via the [Share](/api-reference/payment-links/share) endpoint, a share event was created and stored. You can use the share history to audit which customers received a link, when they received it, and which payment link was shared. You can optionally filter results by `paymentLinkId` to scope the history to a specific link, which is useful for per-link tracking and customer support lookups.

## Endpoint

```
GET https://core.nadapay.io/api/v1/organization/payment-links/shares/history
```

## Request Headers

| Header | Value |
|--------|-------|
| `x-api-key` | `YOUR_API_KEY` |

## Query Parameters

<ParamField query="page" type="number" default="1">
  Page number to retrieve. Starts at `1`.
</ParamField>

<ParamField query="limit" type="number" default="10">
  Number of share events to return per page.
</ParamField>

<ParamField query="sortBy" type="string" default="createdAt">
  Field to sort results by. Defaults to `createdAt`.
</ParamField>

<ParamField query="sortOrder" type="string" default="desc">
  Sort direction. Allowed values: `asc`, `desc`.
</ParamField>

<ParamField query="paymentLinkId" type="string">
  Optional. Filter share events to only those associated with a specific payment link. Pass the `id` of the payment link you want to scope to.
</ParamField>

## Example Request

```bash
curl --request GET \
  --url 'https://core.nadapay.io/api/v1/organization/payment-links/shares/history?page=1&limit=10&sortBy=createdAt&sortOrder=desc&paymentLinkId=pl_abc123' \
  --header 'x-api-key: YOUR_API_KEY'
```

## Response

<ResponseField name="success" type="boolean">
  `true` when the request completes successfully.
</ResponseField>

<ResponseField name="statusCode" type="number">
  HTTP status code — `200` on success.
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable status, e.g. `"Share history retrieved successfully"`.
</ResponseField>

<ResponseField name="data" type="object">
  Paginated result wrapper.

  <Expandable title="data fields">
    <ResponseField name="items" type="array">
      Array of share event objects.

      <Expandable title="share event object fields">
        <ResponseField name="id" type="string">
          Unique identifier for this share event.
        </ResponseField>

        <ResponseField name="paymentLinkId" type="string">
          The ID of the payment link that was shared in this event.
        </ResponseField>

        <ResponseField name="emails" type="array">
          Array of email addresses the payment link was sent to in this event.
        </ResponseField>

        <ResponseField name="metadata" type="object">
          Any metadata attached to this share event at send time — useful for correlating shares with your own records.
        </ResponseField>

        <ResponseField name="createdAt" type="string">
          ISO 8601 timestamp of when the share was sent.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="total" type="number">
      Total number of share events across all pages.
    </ResponseField>

    <ResponseField name="page" type="number">
      The current page number returned.
    </ResponseField>

    <ResponseField name="limit" type="number">
      Number of results per page used for this response.
    </ResponseField>
  </Expandable>
</ResponseField>

    "items": [

        "metadata": {
          "orderId": "ORD-9876"
        },
        "createdAt": "2024-07-01T10:05:00.000Z"
      }

    "limit": 10

<Note>
  Use the `paymentLinkId` query parameter to filter share history down to a specific link when handling a customer support request or auditing outreach for a single campaign. Without that filter, the endpoint returns share events across all payment links under your organization.
</Note>
